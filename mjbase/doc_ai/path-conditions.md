# 路径条件收集与死分支修剪

> 代码：`mjbase/src/mjbase/asm/analyzer/path_conditions.{hpp,cpp}`；
> 用例：`mjbase/test/unittest/asm/analyzer/path_conditions_test.cpp`。

## 背景

`branch_facts` 按操作数形状预测单条条件分支的走向，不保留「为什么」：跨多条分支的同一谓词、相等关系推出的算术结论、以及某条边根本不可行，都超出单点预测的范围。死分支删除需要的是「这个分支在所有到达路径上是否恒定」，这要求把每条分支的谓词贴到控制流边上，再沿路径求交集。

本模块是域条件化层，不是符号执行，更不是 SMT：符号域只承载整数表达式与常量，事实只有原子约束的 must 交集，判定只做常量折叠、同式比较、绑定求值和差式化简。谓词表达式与化简复用 `expr` 模块。

## 模型

```text
常量/参数/运算 ──> SymValue（expr 或未知 + 槽宽）
                              │
                    DomainEngine<SymValue>      控制流、槽迁移、合并
                              │
CFG 边 ──> PathConstraint（taken=谓词，fall-through=否定）
                              │
                    块入口 FactSet（must 交集）──> truthOf / prune
```

- 符号值的身份是产值点：常量与 ldc 折成常量表达式，其余产值点记为 `v<InsnId::slot>`，入参记为 `p<localIdx>`。汇合时结构不同的表达式退化为未知，因此局部值不会跨合并点串味。
- 入参只有在传入 `MethodSig` 时才播种；不传签名时局部槽读不到已写值，每个读点独立成符号，分支条件无法与参数关联。

## 谓词表示

```cpp
struct PathConstraint {
    PathCmp cmp;        // Eq/Ne/Lt/Le/Gt/Ge，JVM 有符号语义
    expr::ExprRef lhs;
    expr::ExprRef rhs;
};
```

谓词覆盖 `IFEQ..IFLE`（单操作数，右操作数补 0）与 `IF_ICMPxx`（双操作数）。常量侧归一到右边，换边时翻转比较方向。`IFNULL`/`IFNONNULL`/`IF_ACMPxx` 与 switch 不建模：对应分支的谓词为空，边上不附加约束，`truthOf` 返回 Unknown。

约束比较是结构相等（表达式节点的位宽与变量名都参与），所以 `x+1 < 6` 与 `x+1 < 5` 是不同原子。

## 事实传播

(1) 入口块事实为空集，其余块取全部入边事实集的交集。交集只保留所有入边共有的原子，某条路径不成立的约束自然被稀释。事实集只收缩，worklist 必然收敛。

(2) taken 边附加谓词，fall-through 边附加其否定；其余边（switch、异常、jsr 顺序边）不附加约束。异常 handler 的入口事实因此只来自各抛出点的交集，不携带任何 catch 语义。

(3) 传播前先用源块事实判定边约束：恒假的边直接不传播，恒真的边不插入原子。插入与源块已知原子矛盾的约束视为不可行边。这样的裁剪让死 try 范围、互斥判断后的块可以整体判不可达，`blockReachable` 为假。

(4) 回路不需要迭代到格顶：首轮 header 只收到入口边的空事实，后向边只有在下一轮才可能带入更弱的事实集。交集语义不会把某次迭代的路径约束错误带到下一轮。

(5) 事实不动点有访问上限（块数 × 64 + 4096）。触发上限说明输入畸形或实现失控，结果置 `PathConditionError::Analysis`，所有查询退回 Unknown（fail-closed）。

## 判定

`truthOf(branch)` 在分支所在块的入口事实上判定其谓词，顺序如下：

(1) 两侧同式：`x==x`、`x<=x` 恒真，`x!=x`、`x<x` 恒假。

(2) 两侧均为常量：直接按有符号整数比较。

(3) 事实集中已有同一原子或其否定：分别判恒真、恒假。

(4) 事实集中的 `var == const` 等式转成变量绑定，对谓词两侧表达式求值。`x==5` 由此可推出 `x+1==6`；同一变量出现两个不同常量时该绑定作废，不参与求值。

(5) 仅对 Eq/Ne，用 `expr::exprSub` 构造差式并化简；差式折成常量时判定。有序比较不走差式，避免把溢出语义不同的变换当成等价。

(6) 其余情况 Unknown。谓词结构超过 512 个节点、化简轮数超过 6 或求值深度超过 256 时同样返回 Unknown，不猜测。

## 查询面

| 查询 | 说明 |
|---|---|
| `summary()` | 引擎帧摘要（栈/局部容量、失败码） |
| `ok()` / `error()` | 分析是否可用；失败面为 `CfgBuild` / `Analysis` |
| `blockOf(insn)` | 指令所属块；无效或不属于本方法返回 `kNoBlock` |
| `blockReachable(block)` | 所有入边是否都被证明不可行 |
| `constraintsAt(block)` | 块入口在所有到达路径上成立的约束（按规范化键序输出） |
| `truthOf(branch)` | 条件分支的 `AlwaysTrue` / `AlwaysFalse` / `Unknown` |

`constraintsAt` 是 must 语义：每条约束分别成立，但不同约束不必来自同一条路径。交集里不会同时出现互补原子，因为插入时已经拒绝。

## 死分支修剪

`pruneDecidedBranches(unit, facts)` 是查询面的消费样例，只改指令、不重构 CFG：

- 恒假：把条件分支改写成 `POP`/`POP2`（按分支弹出的槽数），清空跳转目标。栈效应与原分支一致，顺序后继继续执行。
- 恒真：在分支前插入 `POP`/`POP2` 复现出栈，再把分支改写成 `GOTO_W`。用宽跳转是为了避免插入指令后 16 位偏移放不下。
- 未知：原样保留。

返回值是实际改写的分支句柄。修剪后方法布局已变，调用方必须重建 CFG 和本模块的分析结果，不能拿旧句柄继续查询。事实必须来自同一方法体且收集后未编辑；过期句柄按探测式跳过。

## 可靠性边界

(1) 只推理整数比较。null 检查、引用比较、switch、浮点与数组内容都在模型之外，一律 Unknown。

(2) 符号值不建模字段、数组元素、方法返回值：这些产值点是独立未知符号，只有常量与算术链能传递。因此 `getfield` 两次读同一字段不会被关联。

(3) 不建模窄化转换：`i2b`/`i2s` 等转换返回未知值，不做符号推理，防止把截断语义当成整数恒等。

(4) 不建模溢出：有序比较不使用差式推导；`x+1 > x` 这类受溢出影响的恒真式不会被判定。Eq/Ne 的差式化简仅在 expr 化简能把差式折成常量时生效。

(5) 不可达判定只来自路径事实。异常边不带约束，保守地把 handler 视为可达；这与「宁可少删，不乱删」的修剪策略一致。

## 测试覆盖

用例覆盖常量分支的 taken / fall-through 两个方向、同一参数的嵌套判断在两条臂上的恒真/恒假、边上约束的对外暴露、两路汇合后 Unknown、循环头 Unknown、未播种参数的 Unknown、`x==5` 推出 `x+1==6`、恒真与恒假分支的修剪形态（`GOTO_W` 与 `POP`/`POP2`），以及未知分支不被触碰。
