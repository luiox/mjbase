.. _semantic-annotations:

共享声明注解模型
================

状态：部分落地（JVM 类、字段及方法声明注解可读写，DEX 类声明注解可读）。

注解由类型、具名元素和递归值组成。分析可以持有同一种 ``Annotation``\ ，按描述符
匹配注解，按元素名取值。类、字段、方法等挂载位置由各自的声明或适配器提供。
如同 :ref:`semantic-ast` 中的方法和字段引用，适配器将格式索引解析为符号，
让分析和变换直接使用符号及值。

元素值保留八种 Java 基本类型、字符串、类字面量、枚举常量、嵌套注解和数组。
浮点值保留原始位模式，字符串按 UTF-16 码元持有。类字面量用描述符表示，支持
基本类型、对象、数组和 ``void``\ 。枚举常量用字段 ``MemberKey``\ 表示。
描述符、元素名和枚举字段身份随调用者提供的 ``KeyPool``\ 存活。两种适配器使用
同一个池时，可直接比较符号身份。

.. _semantic-annotations-jvm:

JVM 声明注解读写
----------------

``readJvmAnnotations``\ 在类、字段或方法上读取指定可见性的一组注解。字段和方法
通过名称和描述符精确定位，重载方法各有自己的注解。运行时可见和运行时不可见注解
分别对应 ``Runtime``\ 和 ``Binary``\ 。目标存在但缺少所选属性时返回空表。

``rewriteJvmAnnotations``\ 在独立的 classfile 会话中读取所选注解组。回调可以按注解
类型与元素名修改值，或添加、删除注解。回调返回 ``true``\ 时，适配器替换该组并由
libjbc 写出完整 classfile。返回 ``false``\ 时交还原始字节。其余声明和属性仍由源
classfile 承载。解析、转换和写回失败时返回错误，原始输入仍可用。
回调负责使元素名和元素类型与所引用的注解声明匹配。

.. _semantic-annotations-dex:

DEX 类声明注解读取
------------------

``readDexClassAnnotations``\ 由可选的 ``mjbase_dex``\ 目标提供。适配器将 DEX 的
``RUNTIME``\ 和 ``BUILD``\ 声明注解投影为 ``Runtime``\ 和 ``Binary``\ 。
遇到共享 Java 模型无法表达的元素值时返回 ``Unsupported``\ 。 ``SYSTEM``\ 注解由
DEX 后端保留，例如用于表示签名、注解默认值等格式元数据的系统注解。

不同位置的元数据
----------------

JVM 类型使用注解还需要目标位置及类型路径，代码内的目标可能关联指令或局部
变量区间。方法参数注解依赖参数映射，注解默认值关联注解声明的方法。这些属性
目前由 JVM 后端处理。扩展语义访问时，可让相应的位置模型持有同一种
``Annotation``\ 或 ``AnnotationValue``\ ，保留其位置语义。

已知元数据可按用途提供语义模型，例如类签名的类型结构，以及内部类与外围类的
关系。格式专属属性与未知属性继续由各自的二进制模型持有，以保留原始信息和
写回能力。
