# 方法语义指纹规范（semantic_fp）

分析数据库设计（analysis-database.md §4.2）给出了 semantic_fp 的计算口径，
但只有 recipe：归一化输入、哈希构成、稳定性边界、与存储的接线都没有落到
可实现契约。本文是那份口径的 producer 规范——实现方按本文交付，消费方按
本文的失效语义建立预期。

## 定位

semantic_fp 标识一个方法的**语义内容版本**。两个使用场景：

1. **增量再分析**：方法体未变时，`local_facts` 按
   `(method_id, semantic_fp, config_hash, producer, producer_version)`
   命中旧事实，跳过重算；
2. **失效传播**：方法体编辑后指纹翻转，脏队列与 `deps_hash` 机制据此
   精确失效受影响的摘要与边，而不是整库重算。

它必须满足一条不变量：

> 方法语义变化 ⇒ 指纹必变；分析不可见的字节变化 ⇒ 指纹不变。

违反前者会算错（旧事实配新代码），违反后者是伪增量（改一条指令指纹就翻，
增量机制失效）。本文的全部规范性内容都是这条不变量的展开。

## 规范化输入

指纹的输入是方法的完整语义面，按以下管线归一化后进入哈希。

### 1. 方法头

- 方法名不参与（方法身份已由 `member_id` 承载，名字变化走身份层不走指纹）。
- 描述符参与：描述符变化在身份层已视为删旧建新，指纹里保留是冗余但无害
  （`identity_map` 迁移后的旧指纹不会撞上新方法）。
- 访问标志参与：public→private 这类变化对虚分派与调用合法性是语义的。
- 异常表参与（见第 5 项）。

### 2. 指令流

以**可达指令集的规范序**遍历，不按字节码布局序：

- 可达性 = 从入口按 JVM 汇合语义可达；后继遍历顺序固定
  （successor 按操作数出现顺序），保证同 CFG 必产同序。
- 布局重排（不改 CFG 的指令搬移、对齐填充、死代码增删）不改可达集与
  规范序，指纹不变——混淆器常用这类变换，指纹对它们必须钝感。
- 每条指令产出一条类型化 token：opcode 归一为 token 类型，操作数按下述
  规则解引用后编码。

操作数归一化规则（v1 等价族，逐族定案）：

| 操作数族 | 归一化 | 理由 |
|---|---|---|
| 常量加载（iconst/bipush/sipush/ldc int） | `(int, 值)` 单 token | 分析只见值，不见编码；常量折叠后指纹不动 |
| ldc 常量池字符串 | `(str, modified-UTF-8 字节)` | 字节级，不做 charset 解释 |
| 类型操作数（NEW/CHECKCAST/INSTANCEOF/ANEWARRAY） | 解析后内部名 | 不用 CP 索引 |
| 成员引用（field/method） | `(owner, name, desc)` 三元组 | 不用 CP 索引 |
| invokedynamic | `(name, desc, bootstrap 方法句柄三元组, bootstrap 静态参数值序列)` | 与 indy-resolution 的解析面同一约定 |
| 分支目标 | 方法内规范序指令序号 | pc 会漂移，序号在规范序内稳定 |
| 局部槽位 | 原样参与 | def-use 语义敏感槽位分配；不做重编号归一 |

常量加载等价族是 v1 唯一做跨编码归一的地方，边界明确：只对
「装载立即数到操作数栈」这一族，不扩大到其他编码差异（如 goto 与
反向条件分支的互换不做等价——那是控制流图变化，必须翻指纹）。

### 3. 异常表

每条表项 `(start, end, handler, catch_type)`：范围端点为规范序序号，
`catch_type` 为解析后内部名或通配。异常表变化（增删处理器、调整范围）
翻指纹。

### 4. Code 属性内的语义字段

max_stack、max_locals 参与（帧计算与 def-use 的输入）。StackMapTable
不参与——它是方法体的派生物，方法体不变它不该独立翻转指纹。

### 5. 排除面

调试信息（LNT/LVT/LVTT/SourceFile）、参数名、注解、所有非语义属性不
参与。渲染相关缓存走 `render_fp`（recipe：semantic_fp 之上叠加这些面），
不混用。

## 哈希构造

- 规范序列化：类型化 token 流，变长整数 LEB128、定长字段小端、字符串
  以字节长度前缀 + modified-UTF-8 原始字节；token 流首字节为指纹算法
  版本号（v1 = 0x01）。归一化规则未来任何变化（等价族扩缩、序号方案
  调整）必须升版本号，旧指纹靠版本位自然失配、旧事实保留到 GC。
- 摘要：SHA-256，指纹取 32 字节摘要全文；对外文本形态为 64 位小写 hex。
- 确定性要求：同输入字节跨平台、跨版本必产同指纹。禁止指针值、哈希
  迭代序、平台 size 类型进入序列化；CI 覆盖 Windows/Linux 双端一致。
- 指纹相等按充分条件使用（256 位碰撞不设二次校验），与 `class_fp`
  的 SHA-256 用法同一口径。

## 稳定性语义（编辑 × 指纹期望表）

本表是实现方测试矩阵与消费方预期的共同真源，新增等价族必须先在此表
登记再实现：

| 编辑 | 指纹 | 说明 |
|---|---|---|
| 常量折叠（ldc→iconst 等） | 不变 | 常量加载等价族 |
| 改 opcode（iadd→isub） | 变 | 语义变化 |
| 死代码增删 | 不变 | 可达集不变 |
| 布局重排 / 对齐填充 | 不变 | 规范序不依赖布局 |
| CP 重排 / 索引重写 | 不变 | 全部解引用 |
| 行号 / LVT / 注解修改 | 不变 | 排除面 |
| 新增/删除异常处理器 | 变 | 异常表参与 |
| 访问标志变化 | 变 | 方法头参与 |
| indy bootstrap 参数变化 | 变 | 解引用面 |
| 引用目标的类/成员改名 | 变 | 见下节，有意为之 |

**改名放大效应**：指纹包含被引用名字是设计使然——分析事实（边、摘要）
本来就以名字为出口语义，被引用类改名后旧事实的指向已经失真，翻指纹是
诚实行为。rename 引擎的显示名覆盖（renames 覆盖层）不改字节码，不触发
此效应；真正的字节码级批量改名会造成大范围失效，这是正确成本，不需要
也不应该在此处做豁免机制。

## 与存储的接线

- 写入面：`method_versions` 每版本落 `semantic_fp`；`method_state`
  的 `semantic_fp` 指向当前版本。方法体编辑事务内完成「重算指纹 →
  插新版本 → 更新 state → 标脏」。
- 复用面：`local_facts` 主键含指纹，指纹翻转换档自然 miss，旧事实
  留存待 GC；`edges` 按源方法替换时（analysis-database.md §4.3 的
  写事务约定）携带 `src_semantic_fp`。
- 摘要失效：自身指纹变化走脏队列；被调方变化经 `deps_hash` 传播，
  本规范不重复其机制。
- native / abstract 方法：无 Code 属性，指纹覆盖方法头 + 空指令流 +
  空异常表，语义恒定，编辑访问标志之外的任何东西都不影响它们。

## 实现切面

- 承载：mjbase 分析层新增指纹工具（输入 jbc DOM 的 MethodNode 与
  ConstantPool 解析面，输出 32 字节摘要），不新增第二套解析。
- 测试矩阵：稳定性语义表逐行 golden 用例；规范序对布局重排的钝感
  用例（打乱布局断言指纹不变）；indy 解析面用例；双端确定性用例。
- 验收：同一方法在「CP 重排 + 布局重排 + 死代码删除」三连混淆后
  指纹不变；任一真实语义编辑后指纹必变。

## 边界（v1 明确不做）

- 不做跨方法内容指纹：被调方只进身份三元组，内容依赖由摘要
  `deps_hash` 机制承担。
- 不做深层语义等价（交换律重排操作数等保守方向的多余失效接受不修）。
- 不做反混淆对抗面的鲁棒性（插入无害指令序列等语义保持混淆会翻
  指纹——指纹为增量分析服务，不为对抗服务）。
- 不做指纹迁移：算法版本升级不重算历史指纹，旧档靠 GC 退场。
